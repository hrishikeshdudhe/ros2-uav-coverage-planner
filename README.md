# ROS 2 UAV Coverage Planning

A ROS 2-based coverage-planning framework for defining polygonal areas in RViz and generating coverage paths for unmanned aerial vehicles (UAVs).

The project integrates [OpenNav Coverage](https://github.com/open-navigation/opennav_coverage) with a custom grid-based, STC-inspired coverage planner. Users can select an area on a map, visualize its boundary, and compare the coverage paths generated by both planners.

## Features

- **Interactive polygon selection:** Define a coverage area by clicking points in RViz.
- **Polygon validation and closure:** Close the polygon by clicking near its starting point.
- **OpenNav coverage planning:** Generate coverage paths using the OpenNav Coverage framework.
- **Custom coverage planning:** Generate paths using a grid-based planner that constructs a spanning tree with Depth-First Search (DFS) and traverses the tree with backtracking.
- **Heading calculation:** Assign waypoint orientations according to the direction of travel.
- **RViz visualization:** Display polygon boundaries, coverage paths, and start/end markers.
- **Reset functionality:** Clear the selected polygon and previously generated paths and markers.

## Architecture

The package contains three primary nodes.

| Node | Description |
|---|---|
| `gps_polygon_collector` | Collects clicked points, constructs a polygon, and triggers planning when the polygon is closed. |
| `coverage_client` | Sends the polygon to the OpenNav Coverage action server and publishes the resulting path. |
| `stc_coverage_planner` | Generates a grid-based coverage path using a DFS-built spanning tree and DFS traversal with backtracking. |

### Coverage Planning Workflow

1. The user selects points in RViz using the `clicked_point` topic.
2. The polygon collector stores the points and displays the developing boundary.
3. When the polygon is closed, the collector publishes the completed polygon on `collected_polygon`.
4. The `polygon_ready` topic triggers both planners.
5. The OpenNav client requests a coverage path from the OpenNav Coverage action server.
6. The custom planner discretizes the polygon into a grid, identifies cells inside the polygon, constructs a spanning tree, and traverses it to produce a path.
7. Both paths and their start/end markers are published for visualization in RViz.

## Installation

### 1. Install ROS 2

Install a compatible ROS 2 distribution by following the official instructions:

https://docs.ros.org/en/humble/Installation.html

Source the ROS 2 environment in your terminal:

```bash
source /opt/ros/humble/setup.bash
```

### 2. Install development tools

```bash
sudo apt update
sudo apt install -y \
    git \
    python3-colcon-common-extensions \
    ros-humble-rviz2
```

Install the ROS 2 message packages:

```bash
sudo apt install -y \
    ros-humble-geometry-msgs \
    ros-humble-nav-msgs \
    ros-humble-std-msgs \
    ros-humble-visualization-msgs \
    ros-humble-std-srvs
```

Install OpenNav Coverage and its message definitions using the installation instructions for the compatible ROS 2 distribution:

https://github.com/open-navigation/opennav_coverage

Package availability can vary depending on the ROS 2 distribution. If binary packages are unavailable, follow the upstream repository's source-build instructions.

### 3. Create a workspace

Create a ROS 2 workspace:

```bash
mkdir -p ~/coverage_ws/src
cd ~/coverage_ws/src
```

Clone this repository:

```bash
git clone <YOUR_PUBLIC_REPOSITORY_URL>
```

Replace `<YOUR_PUBLIC_REPOSITORY_URL>` with the URL of your public repository.

### 4. Install package dependencies

Navigate to the workspace root:

```bash
cd ~/coverage_ws
```

Resolve dependencies using `rosdep`:

```bash
sudo apt install -y python3-rosdep
sudo rosdep init
rosdep update
rosdep install --from-paths src --ignore-src -r -y
```

If `rosdep` has already been initialized on your system, skip `sudo rosdep init`.

### 5. Build the workspace

```bash
source /opt/ros/humble/setup.bash

cd ~/coverage_ws
colcon build --symlink-install
```

Source the workspace:

```bash
source install/setup.bash
```

For convenience, you can add the ROS 2 and workspace setup commands to your shell configuration. Ensure the workspace path matches your installation.

## Running the Project

The repository includes launch files for the RViz coverage workflow. The exact launch command depends on the launch-file configuration and the installed OpenNav Coverage server.

### 1. Source the environment

Open a terminal and run:

```bash
source /opt/ros/humble/setup.bash
source ~/coverage_ws/install/setup.bash
```

### 2. Start the coverage-planning system

Launch the configured RViz workflow:

```bash
ros2 launch gps_anchor rviz_coverage_launch.py
```

For the offline visualization configuration, if supported by the installed launch file:

```bash
ros2 launch gps_anchor rviz_coverage_offline_launch.py
```

The launch files must start the required nodes and configure the appropriate topics. The OpenNav Coverage action server must also be available when using the OpenNav planner.

### 3. Define a coverage area

1. Open RViz and select the appropriate fixed frame and map display.
2. Use the `Publish Point` tool to select polygon vertices.
3. Continue clicking until the polygon is complete.
4. Close the polygon by clicking near the starting point, within the configured closure radius.
5. The completed polygon triggers the coverage planners.
6. Inspect the generated paths and their start/end markers.

The custom planner uses the `resolution` parameter to determine grid spacing. Smaller values produce a finer grid and potentially more waypoints, increasing computation and visualization requirements.

## ROS 2 Topics

The following topics are used by the nodes. Their fully qualified names may include a namespace depending on the launch configuration.

| Topic | Type | Purpose |
|---|---|---|
| `clicked_point` | `geometry_msgs/msg/PointStamped` | Receives points selected in RViz. |
| `collected_polygon` | `geometry_msgs/msg/PolygonStamped` | Publishes the completed polygon. |
| `polygon_ready` | `std_msgs/msg/Empty` | Triggers coverage planning. |
| `coverage_reset` | `std_msgs/msg/Empty` | Resets polygon and coverage-planning state. |
| `coverage_path_opennav` | `nav_msgs/msg/Path` | Publishes the OpenNav coverage path. |
| `coverage_path_stc` | `nav_msgs/msg/Path` | Publishes the custom planner's path. |
| `coverage_markers_opennav` | `visualization_msgs/msg/Marker` | Publishes OpenNav start/end markers. |
| `coverage_markers_stc` | `visualization_msgs/msg/Marker` | Publishes custom planner start/end markers. |
| `polygon_marker` | `visualization_msgs/msg/Marker` | Visualizes the selected polygon boundary. |

To inspect the available topics, run:

```bash
ros2 topic list
```

To inspect the polygon:

```bash
ros2 topic echo /collected_polygon
```

If the nodes are running under a namespace, use the fully qualified topic name shown by `ros2 topic list`.

## Custom Planner

The custom planner uses the following stages:

1. **Grid discretization:** Creates a regular grid over the polygon's bounding box.
2. **Polygon filtering:** Retains grid points whose coordinates lie inside the polygon.
3. **Graph construction:** Treats valid cells as nodes connected to their four orthogonal neighbors.
4. **Spanning tree construction:** Uses DFS to construct a spanning tree over the reachable cells.
5. **Tree traversal:** Traverses the tree using DFS, adding parent waypoints during backtracking.
6. **Heading calculation:** Calculates yaw from the direction between consecutive waypoints and converts it to a quaternion.

The resulting path visits the reachable grid cells and includes backtracking along tree edges.

**Algorithm note:** This implementation is STC-inspired rather than a complete classical Spanning Tree Coverage algorithm. It constructs a spanning tree directly over the grid cells inside the polygon, rather than using the complete cell decomposition and traversal procedure of classical STC.

The planner uses four-connected grid neighbors. Depending on the polygon geometry and grid resolution, some cells may be disconnected from the starting cell. Only cells reachable through the constructed tree are included in the traversal.

## Resetting the Planning State

The polygon collector and both planners subscribe to `coverage_reset`.

To request a reset:

```bash
ros2 topic pub --once /coverage_reset std_msgs/msg/Empty "{}"
```

This clears the stored polygon and resets the published paths and markers.

If the nodes use a namespace, publish to the corresponding namespaced topic.

## Limitations

- The planner operates on two-dimensional polygonal areas.
- The custom planner does not implement obstacle avoidance or dynamic replanning.
- Grid resolution affects path density and computational cost.
- The custom planner follows a spanning tree and therefore includes backtracking.
- Heading values describe the orientation associated with path waypoints; they do not constitute a complete UAV attitude or flight controller.
- The generated paths are planning outputs and are not, by themselves, proof of successful autonomous flight.
- Integration with a UAV autopilot or flight controller requires an appropriate downstream interface.
